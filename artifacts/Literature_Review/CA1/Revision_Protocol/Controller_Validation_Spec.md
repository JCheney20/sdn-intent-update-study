# Prospective controller validation policy

25 October 2026. Frozen before the controller outcomes below are executed. Existing original-intent raw fixtures, H=4/5, common C*=75/126 and T*=80/132 remain unchanged. This is an adaptation study, not the full published CCG implementation or a production SDN guarantee.

- Ordinary performs target replacement and close-old/open-new/tag-0 activation atomically at the common ingress in round 1; other changed-switch replacements apply independently that round. It is expected to be a negative control, not granted a free drain phase.
- Q and V retain the already validated schedules. V refuses before network work if the extra-row allowance is below its independently derived one-row staging requirement.
- CCG-inspired uses a conservative located-rule graph over current/proposed rows and positive removed-edge histories. It closes old admission in round 1. Until H full rounds after closure acknowledgement, every possible old-source route must still terminate at the old destination; DROP/cycle/wrong host fails admission of a proposed batch. New admission remains closed until exact target installation and every history-overapproximated new-source route terminates correctly. Positive removed edges survive through acknowledgement+H and expire at the next opening boundary. New historical absence is not retained after an acknowledged insertion. Candidates are visited in fixed lexicographic switch-name order, and cumulative proposed batches are checked together, not only in isolation. Controller choices never inspect probe locations or outcomes.
- This bounded no-rollback CCG-inspired adapter returns explicit PROGRESS_BLOCKED if it cannot issue progress within H waiting rounds plus one command round; it does not silently reset the plan or grant an unimplemented partial-state versioned fallback. Its scope differs from the older continuous-service scheduler. Histories are controller storage, not free forwarding rows; report their peak and maintenance work separately.
- Guard-only evaluates ordinary updating using the candidate numeric engine's complete representative-probe domain. It releases ordinary only on complete PASS. FAIL/INCOMPLETE invokes V before any network action; V's capacity refusal remains visible. It never calls the independent oracle to choose a plan.
- Detector-guided performs the original full snapshot subset/pair search (not an exhaustive-event-set lookup or silently early-stopping optimization). An alert selects V; a negative selects ordinary. Guarded-detector adds the same complete guard before releasing a negative. All fallbacks are fresh plans before any network work and are counted; neither method silently receives Q as a cheaper fallback.
- Capacity is the per-switch maximum endpoint row count plus allowance 0 or 1. Refused methods have zero applied network batches and are not jointly qualified. Blocked/incomplete is not a safety PASS.

Validation uses the already captured reference-compatible k=3/k=20 caches, plus deliberately empty/all-host cache branch controls. These are validation fixtures, not primary or sensitivity observations. All generated plans must meet action/progress bounds and be independently replayed against the raw oracle. Safe claims require complete representative coverage; a failure may stop after an independently valid counterexample. Joint/source-slot/history integration obligations remain explicit; a component test alone is not an all-controller PASS.

Stage 3 may start only after this gate passes for all included controllers and the machine-readable scientific source/grid/attempt/measurement freeze is verified. No outcome-driven switch ordering, seed, topology, threshold or fallback revision is permitted.
