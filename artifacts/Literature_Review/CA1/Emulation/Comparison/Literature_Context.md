# Primary-source context for the emulation extension

Checked 27 October 2026, for manuscript integration after the completed frozen comparison. These references explain method choice and limitations; they do not certify this implementation.

1. **B. Lantz, B. Heller and N. McKeown, “A network in a laptop: rapid prototyping for software-defined networks,” HotNets 2010, pp. 1–6.** DOI: https://doi.org/10.1145/1868447.1868466 . Official conference paper: https://conferences.sigcomm.org/hotnets/2010/papers/a19-lantz.pdf . DOI metadata: https://api.crossref.org/works/10.1145/1868447.1868466 . Paper Sections 3.1–3.3 describe processes/network namespaces, veth links, userspace/kernel switches and a Python API. Section 5 explicitly identifies shared Linux scheduling and limited performance fidelity, particularly at high loads. This supports using actual packet/software behavior as implementation evidence, without converting emulator timing into hardware performance or exhaustive safety. Extracted paper retained under `literature/mininet-hotnets2010.md`.
2. **Mininet official overview:** https://mininet.org/overview/ . Confirms actual Linux applications/network stack, namespace/veth construction and the Python API. Its limitations state that CPU/bandwidth are bounded by one server. Do not quote the current API's kernel-switch default as the chosen backend; this study explicitly uses private userspace OVS.
3. **Open vSwitch 3.2.1 version-matched userspace documentation:** https://github.com/openvswitch/ovs/blob/v3.2.1/Documentation/intro/install/userspace.rst . Describes `datapath_type=netdev`, the existing TUN/TAP requirement and the warning that userspace-only mode without DPDK is experimental and not thoroughly tested. This is separate from the manuscript's earlier OVS 3.5.0 bundle-manual reference. The study did not load modules or build OVS from source merely because the upstream installation text discusses those options.
